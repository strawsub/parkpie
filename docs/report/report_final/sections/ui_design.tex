\section{User Interface Design}

\subsection{Visual Appeal}

The app aims to adhere to the \href{https://developer.apple.com/design/human-interface-guidelines/}{Apple Human Interface Guidelines} where possible. However, to cater for both Android and iOS, the visual components are adopted from \href{https://m3.material.io/}{Google's Material 3} design system.

\begin{itemize}
    \item The app uses a centralized color palette with the brand primary color (\#7FAC58, a calming green) as the visual anchor. Colors are used for confirmation (green), warning (red with varying opacity), status indicators (ingo colors).
    \item Typography is handled through the \emph{Plus Jakarta Sans} font family—a modern, highly readable sans-serif typeface with seven weight variations (Regular, Medium, SemiBold, Bold). The type scale follows proper hierarchy: display/headline size, body text and label text.
    \item Spacing consistency is achieved through eight standardized categories ranging from 4 to 40 pt. Semantic spacing constants also differ depending on the UI components (card, screen, section, etc.) ensure visual rhythm throughout the app.
    \item The app also employs engaging and modern visual components: Lottie animations (on timer screen), smooth border radius, elevation and shadows for buttons, etc.
\end{itemize}

Some interesting design choices that we make include:

\begin{itemize}
    \item The parking detection sheet uses a slide gesture instead of a simple button tap. This prevents accidental timer starts.
    \item Stopping an active timer requires confirmation through a dialog titled ``Stop Timer'' with clear consequence, which prevents accidental timer cancellations
    \item The parking info sheet displays seven days of the week at the bottom to prevent visual clutter.
    \item On the \texttt{Timer} screen, nearby parking zones appear in a horizontal scrollable carousel with clear “Swipe to select a zone” instruction
\end{itemize}

\subsection{Design Guidelines}

Key implementations include:

\begin{itemize}
    \item Navigation \& Structure: Tab bars at the bottom for consistent navigation, visible across screens with occasional hiding for quick actions (e.g., filter configuration, camera output). Navigation hierarchy is shallow (at most two layers from tab bar item), with simple and intuitive icons. Navigation bars are omitted.
    \item Visual Design: Sans-serif fonts ensure readability, with sufficient contrast between text and background. iOS-standard spacing and minimum tap targets (44pt) are respected.
    \item Buttons: Major buttons and search bars are prominently sized. Layout respects safe areas (notch, home indicator, dynamic island). 
    \item Accessibility: Supports seven languages (English (default), Traditional Chinese, Simplified Chinese, Korean, Japanese, Thai, and Vietnamese) for accessibility. This applies to the app interface as well as Gemini's response.
    \item Notification: Notifications are used sparingly, primarily for parking time alerts (e.g., 5 minutes remaining).
\end{itemize}

Across the app, standard Flutter components are consistently applied in place of platform-specific equivalents. Examples include:

\begin{itemize}
    \item Tab bars and buttons maintain consistent styling, sizing, and spacing across screens.
    \item Use of semantic colors consistently for status indication (e.g., yellow and red for parking availability).
\end{itemize}

The app also incorporates intelligent navigation based on user context:

\begin{itemize}
    \item When the timer cannot find parking sign data for the area, the error screen suggests user to ``Scan Sign''. This button transitions to the \texttt{Camera} screen.
    \item After a successful address search, the map automatically zooms into the search location, and applies filter centered on that point, displaying only pins of interest.
\end{itemize}

\subsection{Language and Communication}

\begin{itemize}
    \item Button labels are kept between 1-3 actionable words and avoid jargons
    \item Tone is overall friendly, except for the error messages that are explanatory
    \item Use of L10n localizable strings to enforce consistent use of language throughout
    \item Consistent terminology. For instance, a parking zone is the area to which one parking restriction applies to.
    \item Detailed permission messages on the first launch, and privacy policy accessible thereafter
\end{itemize}
