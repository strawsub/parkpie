\subsubsection{Prerequisites}
\begin{itemize}[noitemsep]
  \item Git (to clone repository).
  \item Flutter SDK (recommended: Flutter 3.x or newer). Ensure \texttt{flutter} is on PATH.
  \item Android SDK / Xcode (for mobile targets) if you plan to run on device or simulator/emulator.
  \item Java 11+ (LTS) or as required by the backend (check \texttt{build.gradle} / \texttt{pom.xml}).
  \item Maven or Gradle wrapper (the project may include \texttt{mvnw} or \texttt{gradlew}).
  \item An RDBMS if the backend requires one (PostgreSQL, MySQL, etc.) — check backend configuration.
  \item Optional: Docker / docker-compose if you prefer containerized runtimes.
\end{itemize}

\paragraph{Identify project layout}
Open a terminal in the repository root and locate Flutter and Spring Boot modules:

\begin{verbatim}
# from repo root
# find Flutter project (look for pubspec.yaml)
find . -maxdepth 3 -name "pubspec.yaml"

# find backend (look for build.gradle, settings.gradle, or pom.xml)
find . -maxdepth 3 -name "build.gradle" -o -name "pom.xml" -o -name "settings.gradle"
\end{verbatim}

Typical results:
\begin{itemize}
  \item Flutter app folder contains \texttt{pubspec.yaml}.
  \item Backend folder contains \texttt{build.gradle} or \texttt{pom.xml} and \texttt{src/main/java}.
\end{itemize}

Replace the folder names in the commands below with the actual paths you found (examples: \texttt{frontend/}, \texttt{app/}, \texttt{backend/}, \texttt{server/}).

\subsubsection{Backend (Spring Boot) — build \& run}
\paragraph{Common checks}
\begin{verbatim}
# change to backend directory
cd backend   # or replace with actual backend dir
\end{verbatim}

Open \texttt{src/main/resources/application.properties} or \texttt{application.yml} to identify:
\begin{itemize}
  \item server.port (default 8080)
  \item datasource URL, username, password
  \item profile settings (e.g. spring.profiles.active)
\end{itemize}

\paragraph{Run with wrapper (preferred if present)}
\begin{verbatim}
# If using Maven wrapper
./mvnw spring-boot:run

# OR if using Gradle wrapper
./gradlew bootRun
\end{verbatim}

\paragraph{Build a jar and run}
\begin{verbatim}
# Build
./mvnw clean package    # Maven
# OR
./gradlew clean bootJar # Gradle

# Run the produced jar (example)
java -jar build/libs/your-backend.jar
\end{verbatim}

\paragraph{Environment variables / profiles}
If the backend expects environment variables, export them before starting:
\begin{verbatim}
export SPRING_DATASOURCE_URL="jdbc:postgresql://localhost:5432/parkpie"
export SPRING_DATASOURCE_USERNAME="parkpie"
export SPRING_DATASOURCE_PASSWORD="password"
export SPRING_PROFILES_ACTIVE=dev
\end{verbatim}
Adjust names according to the configuration keys in \texttt{application.properties}.

\paragraph{Database initialization}
If the project uses an RDBMS:
\begin{itemize}
  \item Check for \texttt{schema.sql} or DB migration tooling (Flyway, Liquibase) in the backend.
  \item If migrations exist (e.g., Flyway), they typically run automatically on startup.
  \item Alternatively, run provided SQL scripts to create schema and seed data.
\end{itemize}

\subsubsection{Frontend (Flutter) — build \& run}
\paragraph{Setup and dependencies}
\begin{verbatim}
# change to the Flutter project folder
cd frontend   # or replace with actual flutter app dir

# fetch packages
flutter pub get
\end{verbatim}

\paragraph{Run on device / emulator}
\begin{verbatim}
# list devices
flutter devices

# run on the default connected device
flutter run

# run on a specific device id
flutter run -d <device-id>
\end{verbatim}

\paragraph{Build release artifacts}
\begin{verbatim}
# Android APK
flutter build apk --release

# Android App Bundle
flutter build appbundle

# iOS (macOS host with Xcode)
flutter build ios --release

# Web
flutter build web
\end{verbatim}

\paragraph{Backend API endpoint configuration}
The Flutter app will call the backend API. Locate where the base API URL is configured (common places: \texttt{lib/constants.dart}, environment files, or flavors). Example replacements:
\begin{verbatim}
# in development, point to local backend
API_BASE_URL = "http://10.0.2.2:8080"   # Android emulator uses 10.0.2.2 to reach host
# or from host to iOS simulator
API_BASE_URL = "http://localhost:8080"
\end{verbatim}

\subsubsection{Running both locally}
Open two terminals:

\begin{enumerate}
  \item Terminal A: start the backend (see Section 3).
  \item Terminal B: start the Flutter app (see Section 4).
\end{enumerate}

For the Flutter app, it's usually easiest to run locally (not containerized), but you can serve the web build via an nginx container if desired.

\subsubsection{Tests}
\begin{itemize}
  \item Backend: run \texttt{./mvnw test} or \texttt{./gradlew test}.
  \item Flutter: run \texttt{flutter test}.
\end{itemize}
